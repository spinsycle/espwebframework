# F1 hardware checklist: mDNS (.local name)

Flash firmware and UI (`run -t upload`, then `run -t uploadfs`). `uploadfs` wipes saved settings, **including the password**: the board comes back on the factory password `espframework` and makes you change it. Redo the Network save (Wi-Fi client, mode Both) after.
Tick each row on the NodeMCU; the ESP32 column stays open until the board arrives. Have a PC and a phone on the same Wi-Fi as the board.

| # | Check | NodeMCU | ESP32 |
|---|-------|---------|-------|
| 1 | Network tab shows a new box "Name on your network (mDNS)", unticked, with the name field hidden. Tick it: the Name field appears. Type `relays`: the line under it reads `Reach this board at http://relays.local ...` | | |
| 2 | Default is off: on a freshly wiped board, Dashboard / System shows no `.local` name and `ping relays.local` from the PC fails | | |
| 3 | Tick it, name `relays`, Save and apply. Reconnect to the board by its IP. `GET /api/v1/status` (or the Dashboard) shows `network.mdns` with `enabled: true`, `active: true`, `name: relays.local` | | |
| 4 | PC: `ping relays.local` answers with the board's IP. `http://relays.local` opens the dashboard and you can sign in | | |
| 5 | Phone: `http://relays.local` opens on iOS. On Android note whether it opens (some browsers do not resolve `.local`): Result: ______ | | |
| 6 | The IP did not change when you turned it on (same address as before in Dashboard / Wi-Fi client) | | |
| 7 | Rename to `valves`, Save. After the reconnect `valves.local` works and `relays.local` stops answering within a minute or two (cached answers on the PC may linger) | | |
| 8 | Untick it, Save. `valves.local` stops resolving, the board is still on the same IP, and `network.mdns.active` is false | | |
| 9 | Enabling with an empty name, a name with a space, or `a.b` is refused ("Rejected: invalid_network_config (mdns.name)") | | |
| 10 | Mode `Access point only` with mDNS ticked: saves fine, the board stays at 192.168.73.1, `network.mdns.active` is false (no `.local` name in AP-only mode) | | |
| 11 | Switch back to Both with mDNS ticked, restart the board (System tab): the name comes back by itself after the board rejoins Wi-Fi | | |
| 12 | Pull the router's power for a minute and restore it: the board rejoins and `relays.local` works again without touching the board | | |
| 13 | After an hour on, Diagnostics memory (free, lowest) has not dropped below the P9 figure (lowest about 6.4 KB) and the page still loads quickly | | |
