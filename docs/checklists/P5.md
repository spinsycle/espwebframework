# P5 hardware checklist: config system (edit, export, import, factory reset)

Flash firmware and UI (`run -t upload`, then `run -t uploadfs`; uploadfs wipes saved settings, so redo the Network save once).
Use the board's own network (`http://192.168.73.1/`) if the home router is slow to let the board join.
Tick each row on the NodeMCU; the ESP32 column stays open until the board arrives.

Before you start: on the Devices tab add a relay `r1` on GPIO14 and a PWM device `p1` on GPIO12 (nothing needs to be wired), so there is something to export.

| # | Check | NodeMCU | ESP32 |
|---|-------|---------|-------|
| 1 | Devices tab: every card has an **edit** button. Click it on `r1`: the form switches to "Edit r1", the ID and Type boxes are locked, and the fields hold the relay's values | | |
| 2 | Change the name to `Light` and save: "Saved.", the card shows the new name within a second, the form goes back to "Add device" | | |
| 3 | Edit `r1` and change its pin to 5: the card now says GPIO5. Edit it back to 14. Reboot the board: it comes back with the pin you last saved | | |
| 4 | Edit `r1` and set its pin to 12 (the PWM device's pin): rejected `pin_in_use`, the card is unchanged | | |
| 5 | Edit `p1`'s frequency from 1000 to 500: accepted (it is the only PWM device). Edit it back | | |
| 6 | Edit a relay that is ON: after saving it returns to its "At boot" value (documented: an edit restarts the device) | | |
| 7 | System tab, **Export devices**: a file `espwf-config.json` downloads. Open it in a text editor: it lists `r1` and `p1`, has `"schema_version":1`, and contains no Wi-Fi password | | |
| 8 | Remove both devices on the Devices tab. System tab, choose the exported file, **Import (replace all)**, confirm: the board restarts and both devices are back with the same settings | | |
| 9 | Edit the exported file: change `p1`'s id to `r1` (a duplicate) and import it. The page says "Rejected at device 2 'r1': duplicate_id. Nothing was changed." and the board does **not** restart | | |
| 10 | Edit the file again: set `"schema_version":99`. Import: rejected `unsupported_schema`, nothing changed. Delete the line entirely: it imports fine (old files count as version 1) | | |
| 11 | Import a file that is not JSON (rename a .txt to .json): "Rejected", nothing changed, the board stays up | | |
| 12 | Import a file with `"devices":[]`: after the restart the Devices tab is empty (this is replace-all) | | |
| 13 | Import the good export again to restore, then **Factory reset**, cancel the first confirm: nothing happens | | |
| 14 | Factory reset, confirm: the board restarts in its **own access point** (`ESPWF-xxxxxx`, password `espframework`), the Devices tab is empty and the dashboard still loads (the UI files survive) | | |
| 15 | After row 14, the Network tab shows the defaults (AP mode, no saved Wi-Fi). Set your Wi-Fi again if you want it back | | |
| 16 | Power-cut test: add a device, then pull the USB cable right after the "Added" message. Reconnect: the device is there (or, at worst, the previous list is: never an empty or half-written list) | | |
| 17 | `tools\api_smoke.ps1 -Ip <ip>`: all checks pass (it adds and removes `smoke_*` devices only) | | |
| 18 | Heap: after rows 7-12 the Dashboard heap is still above 15 KB free and does not keep shrinking | | |
